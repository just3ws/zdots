**Verdict:** Phoenix works cleanly with local llama.cpp via OpenInference. One-liner setup — no cloud egress, traces visible in 30s. The only gap vs O2: Phoenix is ephemeral (in-memory SQLite), no persistent store. For persistent gen_ai tracing, the pattern is: OpenInference instrumentation → existing OTel collector → O2 (already wired). Phoenix is best used as a local eval/debug loop, not a replacement for O2.

**Langfuse eval (S2b):** deferred — Phoenix alone satisfies the gen_ai tracing need. Langfuse adds prompt management; not needed until prompts require versioning.
